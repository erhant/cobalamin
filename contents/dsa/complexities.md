# Complexities

Big-O describes how cost **grows** with input size $n$, ignoring constant factors and small inputs. It is the first filter for any approach: compare the growth rate against the input bounds before writing code.

## Definitions

For functions $f, g$ of $n$:

| Notation             | Meaning                               | Formally                                                   |
| -------------------- | ------------------------------------- | ---------------------------------------------------------- |
| $f = O(g)$           | grows **at most** like $g$            | $\exists c, n_0.\ \forall n \ge n_0.\ f(n) \le c \cdot g(n)$ |
| $f = \Omega(g)$      | grows **at least** like $g$           | $\exists c > 0, n_0.\ \forall n \ge n_0.\ f(n) \ge c \cdot g(n)$ |
| $f = \Theta(g)$      | grows **exactly** like $g$            | $f = O(g)$ and $f = \Omega(g)$                             |
| $f = o(g)$           | grows **strictly slower** than $g$    | $f(n) / g(n) \to 0$                                        |

In practice "$O$" is used loosely to mean $\Theta$: "binary search is $O(\log n)$" means it takes about $\log n$ steps, not merely at most. [Asymptotics](../cryptography/asymptotics.md) applies the same machinery to security, where "negligible" means $o(1/n^c)$ for every $c$.

The table is calibrated to about $10^8$ simple operations per second, a fair estimate for JS or C++ in a judge:

| Class         | Name         | Typical source                                   | Max $n$ in ~1 s     |
| ------------- | ------------ | ------------------------------------------------ | ------------------- |
| $O(1)$        | constant     | array index, hash lookup                         | any                 |
| $O(\log n)$   | logarithmic  | binary search, balanced tree, heap push/pop      | any                 |
| $O(\sqrt n)$  | square root  | trial division, sqrt decomposition               | $\sim 10^{16}$      |
| $O(n)$        | linear       | one pass, two pointers, prefix sums              | $\sim 10^8$         |
| $O(n \log n)$ | linearithmic | sorting, $n$ heap or segment-tree operations     | $\sim 5 \cdot 10^6$ |
| $O(n^2)$      | quadratic    | all pairs, 2D DP                                 | $\sim 10^4$         |
| $O(n^3)$      | cubic        | Floyd-Warshall, interval DP                      | $\sim 500$          |
| $O(2^n)$      | exponential  | all subsets, bitmask DP ($O(2^n n)$)             | $\sim 25$           |
| $O(n!)$       | factorial    | all permutations                                 | $\sim 11$           |

Read it backwards in contests: $n \le 2 \cdot 10^5$ asks for $O(n \log n)$ or better, $n \le 20$ invites bitmasks, $n \le 500$ allows $O(n^3)$.

## Rules of Thumb

- **Drop constants and lower terms**: $3n^2 + 10n + 7 = O(n^2)$.
- **Log base doesn't matter**: $\log_2 n = \log_{10} n / \log_{10} 2$, a constant factor.
- **Sequential steps add, nested loops multiply**: a sort and then a scan is $O(n \log n + n) = O(n \log n)$. A scan inside a scan is $O(n^2)$.
- **Watch for hidden loops**: `arr.includes`, `slice`, spread, string concatenation in a loop, and `shift()` on an array are all $O(n)$.
- **Several inputs keep their own variables**: a graph algorithm is $O(V + E)$, not $O(n)$; a grid is $O(R \cdot C)$.
- **Amortized** cost averages over a sequence. `push` on a dynamic array is $O(1)$ amortized even though an occasional resize is $O(n)$. Union-Find's $O(\alpha(n))$ is amortized too.
- **Space counts the recursion stack**: a DFS over a path-shaped tree uses $O(n)$ stack even with no extra arrays.

## Recurrences

Divide-and-conquer costs come from recurrences. The common ones:

| Recurrence                   | Solution        | Example                         |
| ---------------------------- | --------------- | ------------------------------- |
| $T(n) = T(n/2) + O(1)$       | $O(\log n)$     | binary search                   |
| $T(n) = T(n/2) + O(n)$       | $O(n)$          | quickselect (expected)          |
| $T(n) = 2T(n/2) + O(1)$      | $O(n)$          | tree traversal, segment tree build |
| $T(n) = 2T(n/2) + O(n)$      | $O(n \log n)$   | merge sort                      |
| $T(n) = T(n - 1) + O(1)$     | $O(n)$          | linear recursion                |
| $T(n) = T(n - 1) + O(n)$     | $O(n^2)$        | naive quicksort worst case      |
| $T(n) = 2T(n - 1) + O(1)$    | $O(2^n)$        | Tower of Hanoi, include/exclude subsets |

The general tool for $T(n) = a\,T(n/b) + O(n^d)$ is the **master theorem**: compare $d$ with $\log_b a$. If $d > \log_b a$ the top level dominates, giving $O(n^d)$. If they are equal every level costs the same, giving $O(n^d \log n)$. If $d < \log_b a$ the leaves dominate, giving $O(n^{\log_b a})$.
